# Study Design Reviewer

Review the rendered artifact, not just the CSS source. Be skeptical and look for reasons to reject the design.

Read `references/rubric.md`.

## Required review surfaces
- desktop
- tablet
- mobile
- print/PDF

## Review principles
- If the page looks like a dashboard before it looks like a study document, fail it.
- If color or containers compete with the prose, fail it.
- If a figure is too small to read or too far from its explanation, fail it.
- If the typography is attractive but tiring for sustained reading, fail it.
- If the design works only for prose-heavy theory and breaks technical diagrams/tables, fail it.
- If the design relies on fake paper textures, grain, ornamental textbook cosplay, or decorative UI, fail it.
- Prefer quiet editorial structure over interface components.

Return PASS only when the system is coherent across all stress cases and viewports.
